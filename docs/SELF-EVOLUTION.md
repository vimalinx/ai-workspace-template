
# Self Evolution — 可控的工作区自进化

工作区可以积累经验、流程和政策，但不能让执行者在工作过程中随意改写约束自己的规则。

## 三个权限环

### 内容环

Agent 可在当前任务授权内创建和更新 Agenda、Search、Hypothesis、Experiment、Evaluation、Assignment、事件、raw knowledge、README 同步、派生索引和精确债务。

### 流程环

重复成功的过程可以提出 Skill 草案。正式晋升要求：多个真实案例；成功和失败；适用条件；输入输出；失败路径；验证；回滚；fresh-context review；明确负责人。没有证据的 Prompt 不晋升为 Skill。

### 宪法环

以下变化必须 RFC：修改 `AGENTS.md` 核心不变量；新增顶层层级；改变事实源；改变对象字段或状态语义；改变权限和 Git 规则；自动化外部写入；知识晋升门槛。

## RFC 流程

1. 在 `docs/decisions/` 写问题、动机、替代方案和不做的后果。
2. 列出受影响的文件、对象、旧版本和现有工作区。
3. 在 `governance/migrations/` 写迁移和回滚。
4. 先添加能失败的负向测试，再添加正常通过测试。
5. 生成审阅 diff；获得明确授权。
6. 应用后运行全量测试、协议校验、审计和 release check。
7. 保留旧证据、迁移回执和 superseded 指针。

## 数据逐级压实

信息从事件到政策逐级增加结构：来源、环境、反例、适用边界、置信度和验证入口。压实不是删除历史；低层材料可以归档，但高层结论必须能沿引用回到真实证据。

## 防止自我授权

Agent不能通过先修改 policy/Schema 再执行原本无权执行的动作。授权以任务开始时有效的规则和人类明确指令为准；规则变更本身完成后，新的高风险权限仍需单独授权。
