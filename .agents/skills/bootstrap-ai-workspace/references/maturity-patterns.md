# Domain-neutral maturity patterns

Use a mature reference workspace as evidence that the following relationships work together. Never copy its business names, accounts, hosts, ports, schedules, or credential boundaries into another domain.

## Requirement matrix

| Invariant | Generic implementation | Proof expected |
|---|---|---|
| Intent routes work | Root instructions map work types to layers | A new task has one obvious entry path |
| Lifecycle is explicit | Workbench, durable projects, operated services, reusable tools, archive | Graduation and retirement criteria are documented |
| Dynamic facts have one owner | Filesystem plus machine-readable governance and knowledge catalogs | Other prose links to facts instead of copying tables |
| Rules reconcile to reality | Audit issues have stable code, subject, and remediation | Positive and negative fixtures prove each check executes |
| Commits are gated | A tested pre-commit entry checks staged scope, runtime artifacts, secrets, and audit errors | Hook installation is separately observed, not assumed |
| Maintenance stays bounded | Periodic work only observes and refreshes reproducible reports | Desired automation is distinct from installed state |
| Warnings are accountable | Exact `(check, subject)` debt with owner, reason, and due date | No unowned warning is reported as green |
| Raw knowledge has an exit | Dated raw observations expire into curation, deletion, or debt | Curated claims cite evidence and boundaries |
| AI work is verifiable | A local-private ledger retains sessions, experiments, failed/passed runs, and decisions | Important conclusions cite real evidence IDs or artifacts |

## Four truth layers

1. Normative truth: what must or must not happen.
2. Current operational truth: what exists, who owns it, and its current declared state.
3. Evidence truth: what was actually tried and observed.
4. Reusable knowledge: which validated conclusions survive the task.

A report is derived state, not another authority. A conversation is not evidence until linked to an experiment or decision. Evidence is not reusable knowledge until reviewed and bounded.

## Graduation, retirement, and adaptation

Start ambiguous work in a workbench. Promote it only when the owner, purpose, entry point, status, validation, and operating boundary are known. Put continuously operated components in services and deterministic reusable executors in tools.

Retirement requires a reason, replacement or recovery boundary, and a tombstone or catalog transition. Preserve the target's native business topology; the invariant is accountable lifecycle and reconciliation, not universal folder names.
